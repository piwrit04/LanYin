# 公告板 Noticeboard 1.4.2

作者：星澪 · GPL-2.0-or-later

这是独立的 Windows OBS 原生公告来源，和澜音点歌功能相互独立，不依赖也不修改澜音的覆盖层或插件。

像 OBS 自带的「文本」一样，在 **来源 → + → 公告板** 里直接添加。
不需要另外开网页服务，也不会再弹出黑色窗口。

- 半透明深色圆角卡片 + 暖色细边框
- 可以放 1～20 条公告，每条有「标题（可不填）」和「正文」
- 固定显示一条（手动切换），或者自动轮播
- 卡片宽度按每条公告的最长文本行自适应，高度由字号、行数、间距撑开；拖动仅使用 OBS 原生缩放
- 「启用正文滚动」独立开关，默认关闭；开启后可分别设置水平/垂直循环速度，短文字也能滚动
- **先改草稿，点「应用到直播」才生效**：属性窗口里的预览显示草稿（右上角有「草稿预览 · 未应用」标记），观众看到的还是旧内容
- 上一条 / 下一条 / 暂停 / 从头播放：属性窗口里有按钮，也可以在「设置 → 快捷键」里设快捷键
- 所有设置跟着场景集合一起保存

适用：Windows 64 位，OBS Studio 32.x（在 32.2.2 上测试）。

## 安装（三步）

本目录提供源码与精选真实渲染预览，不附带私人安装包或第三方二进制。先按下方构建说明生成 zip。

1. 关掉 OBS。
2. 解压 `obs-noticeboard-1.4.2-windows-x64.zip`，双击里面的 `install.cmd`。
   （它会把插件复制到 `%ProgramData%\obs-studio\plugins\obs-noticeboard\`，不会改 OBS 的设置和场景。）
3. 打开 OBS，在「来源」下面点 **+**，选 **公告板**，起个名字，确定。

> 也可以手动装：把 `obs-plugins` 和 `data` 两个文件夹复制到 OBS 安装目录
> （一般是 `%ProgramFiles%\obs-studio\`）里合并即可。

卸载：双击 `uninstall.cmd`（或者删掉 `%ProgramData%\obs-studio\plugins\obs-noticeboard` 文件夹）。

## 怎么用

双击公告板来源，打开属性窗口：

**常用面板**
- **直播显示（已应用）**：只列出已经应用、启用且非空的公告；选择后立即切换。草稿不会被误发布。
- **应用到直播**：发布当前全部草稿。新增、删除后会立即刷新同一个窗口里的直播列表。
- **编辑公告（草稿）**：列出全部公告，包括新建空白条目、停用条目；每次只显示选中这一条的编辑区。添加后自动选中新增公告。
- 字体使用与 OBS 相同的原生字体选择控件；正文和标题可分别设置。
- **正文**：默认一行紧凑编辑，`\n` 表示换行，`\\` 表示一个反斜杠；已有多行内容不会被压成一行或丢失。需要直接回车编辑时勾「展开多行编辑」，只展开当前这一条。
- 添加 / 删除当前公告；方案预设与颜色预设两个独立下拉；文字颜色/不透明度；背景颜色/不透明度；水平对齐；**轮廓**；**启用正文滚动**。
- **轮廓**：默认关闭；开启后展开大小（1～20px）、颜色、不透明度，标题和正文都生效。轮廓按字形边缘实际描边，自动留出边缘空间，不是偏移阴影。
- **滚动**：参照 OBS 内置 Scroll 的有符号速度：水平/垂直各 -500～500 像素/秒；正水平向左、负水平向右，正垂直向上、负垂直向下；0 停止该轴。两个方向可同时使用，循环的是正文，标题固定。两轴默认均 0。
- 高级设置可限制滚动窗口最大高度（默认 240px）及宽度（默认不限，启用后 640px）；短文本无需溢出也能滚动。关闭滚动恢复自然宽高，修改仍需「应用到直播」。
- **旧版兼容**：1.3 已开启的溢出滚动继续保留原速度/顶部底部停留，界面有明确说明；调整任一新方向速度，或关闭后重新开启滚动，才切换为新循环方式。不会把旧 `speed` 字段偷偷解释成新速度。

**高级设置**（默认收起）
撤销草稿、暂停、从头播放、播放方式（固定/轮播）、轮播间隔、边框、圆角、内边距、行高、滚动窗口限制、淡入淡出；兼容旧版时还可调整原溢出滚动停留。

**两组独立预设（不是一个十二项下拉）**
- **颜色预设**（实际属性 key：`color_preset`）：原有暖夜/白卡/樱花/墨青/玻璃/夜紫 **6 套 + 自定义**，原 ID `warm / ivory / sakura / ink / glass / violet` 不变。只改标题、正文、背景、边框及轮廓的 RGB 配色，不改字体、字号、不透明度、轮廓开关/粗细、圆角、留白或滚动。
- **方案预设**（实际属性 key：`scheme_preset`）：以下 **6 套场景方案 + 自定义**，只改字体、字重、字号、不透明度、轮廓开关/粗细、行距、圆角、内边距等。**也保留当前配色**；因此可以先选任意场景，再反复换色，不会丢掉字体、透明度或布局。
- 两组各自记录「自定义」：改配色只让颜色组变为自定义；改字体/不透明度/轮廓粗细/留白只让方案组变为自定义。仅改变滚动、正文、播放不会影响任一组。



| 场景 | 字体 / 正文字号 | 背景不透明度 | 主要区别 |
|---|---|---|---|
| 游戏角落提示 | 微软雅黑 UI / 24 粗体 | 28% | 2px 轮廓、小圆角、小内边距 |
| 聊天公告 | 等线 / 26 | 72% | 舒展行距、半透明卡片 |
| 底部字幕条 | 黑体 / 36 粗体 | 58% | 2px 轮廓、直角、紧凑行距 |
| 醒目提醒 | 微软雅黑 / 40 粗体 | 96% | 粗边框、大字、2px 轮廓 |
| 低干扰透明字 | 微软雅黑 UI / 22 | 0% | 文字 72%、1px 轮廓、无边框 |
| 纸卡便签 | 楷体 / 30 | 95% | 近直角、宽内边距；可搭配白卡配色 |

选择预设只更改样式，不改正文、公告数量、当前条、滚动参数或 OBS 场景变换，也不会自动应用到直播。分别保存两组选择，应用、撤销草稿、重开窗口和保存重载都保留独立状态。升级 1.3/1.4 时，旧 `preset` 键仍保留；只按实际样式识别两个新标签，**不重新套用旧预设、不改变现有样式**。不匹配就显示该组「自定义」。使用 Windows 常见中文字体和系统字体映射/Font Linking 回退，不下载字体。

预设字段归属、兼容和测试细节：`docs/preset-ownership.md`。真实离屏渲染对比：[36 组预设组合](docs/previews/1.4.1-preset-contact-sheet.png)。

**1.4.2 连续输入修复**
普通滑块、数字框、颜色、字号、标题和正文编辑不再重建整个属性窗口；从命名预设第一次手调也一样。未增加 debounce 或自动发布。
为保住拖动和光标，预设标签、状态及选择列表标题会在下一次结构操作/按钮操作或重开属性时更新；真实草稿值和独立 Custom 标记立即记录。当前仍显示同名预设而想重套时，可先选自定义再选预设，或重开属性。
OBS 原生逐值保存草稿仍正常，只有「应用到直播」才发布。详细源码证据和测试限制见 `docs/input-stability.md`。

**尺寸和 OBS 变换**
每条公告分别按 GDI 测量自然宽度；手动换行决定行数。切换公告时原生来源尺寸可随内容变化。
OBS 场景中拖动边框只缩放：不会写入宽度、重排文字或重置 scale；不同场景实例的缩放互不干扰。
旧版保存的宽高字段会保留，但不再决定排版；原有标题、正文、启用状态和已应用快照沿用，无需新建来源。

> 小提示：属性窗口的「确定」只是保存草稿；要让观众看到，一定要点「应用到直播」。
> 关掉属性窗口时如果点「取消」，只会撤销草稿，已经应用到直播的内容不受影响。

**「应用到直播」的位置**：仍保留原位置。OBS 32.2.2 公开 properties/frontend API 不能把插件按钮加入底部原生「确定 / 取消」按钮栏；本版没有修改 OBS、注入 Qt 或劫持「确定」的保存草稿行为。证据见 `docs/obs-button-api.md`。

**快捷键**：OBS「设置 → 快捷键」里找到你的公告板来源，有
「公告板：上一条 / 下一条 / 暂停 / 继续 / 当前这条从头播放」。

## 和网页版的区别

| | 网页方案 | 原生插件 |
|---|---|---|
| 运行 | 要开 Python 服务（黑窗口） | OBS 自己加载，无额外窗口 |
| 编辑 | 自定义停靠面板 | 来源的属性窗口 |
| 公告条数 | 最多 40 | 最多 20 |
| 草稿预览 | 停靠面板里 | 属性窗口预览（以及工作室模式的「预览」画面） |

其他已知限制：
- 文字用 Windows GDI 排版：彩色 emoji 会显示成单色线条图形；不支持 HTML / 富文本（和网页版一样是纯文本）。
- 安全边界：卡片最大 4096×4096px；极端超宽文本在 4096px 安全宽度处折行。正文纹理最高 16384px，且单段位图最多 8Mi 像素；超过渲染上限的部分不显示，但原文仍完整保存在草稿/快照中。滚动关闭时不会为了读出超出上限的文字而偷偷滚动。
- 工作室模式的「预览」、场景投影窗口、多视图里的场景，会和属性窗口一样显示草稿（右上角有标记）；
  推流、录像、虚拟摄像头、「节目」画面永远只显示已应用的内容。
- 只支持 Windows。

## 自己编译

依赖：CMake ≥3.16、Ninja、MinGW-w64 x86-64 C 编译器、Python 3；OBS Studio 32.2.2 源码的 libobs 头文件，以及你自己的匹配 Windows x64 `obs.dll`。依赖不随仓库分发，不要把它们提交进源码目录。MSVC 未在此导出副本重新测试。

以下命令从本目录执行。`OBS_SRC` 指向你取得的 OBS 源码根目录；`OBS_LIB` 指向匹配的 OBS DLL。这里不包含个人机器路径。

```bash
# 先在当前终端设置 OBS_SRC 和 OBS_LIB，再构建。
# 例如 OBS_SRC=../obs-studio；OBS_LIB=../obs-runtime/obs.dll
cmake -S . -B build -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE=cmake/mingw-w64.cmake \
  -DOBS_SOURCE_DIR="$OBS_SRC" -DOBS_LINK_LIBRARY="$OBS_LIB"
cmake --build build
cmake --install build --prefix dist
python3 tools/package.py
```

生成 `obs-noticeboard-1.4.2-windows-x64.zip`；版本从 `src/nb-version.h` 读取。打包采用运行时文件白名单，不收集 OBS 官方 DLL/头文件、日志、配置或临时构建目录。源码公开署名已统一为星澪，编译得到的 DLL 不是私人已安装文件的逐字节副本，不能冒称两者 hash 相同。

### 测试

播放时间线单元测试可在 Linux 上运行：

```bash
mkdir -p build-player
cc -std=c11 -Wall -Wextra tests/test_player.c src/nb-player.c -lm -o build-player/test_player
./build-player/test_player
```

编译真实 OBS headless harness（Windows x64 可执行文件）：

```bash
x86_64-w64-mingw32-gcc -std=gnu11 -Wall -Wextra -Wno-unused-parameter -O2 \
  -Icmake -I"$OBS_SRC/libobs" tests/obs_harness.c "$OBS_LIB" \
  -lgdi32 -luser32 -static-libgcc -o build/obs-harness.exe
```

在 Windows 上，从匹配 OBS 的 `bin/64bit` 目录运行此测试程序，传入三个参数：待测插件 DLL、插件 data 目录、新建的测试输出目录。所有路径由运行者提供；输出目录必须先建立，且不应指向真实用户配置。

```text
obs-harness.exe "<plugin-dll>" "<plugin-data>" "<test-output>"
```

测试使用隔离的 OBS 配置和离屏 D3D11，不需要打开 OBS UI，也不会更改真实场景。覆盖自然尺寸、原生 scale、add/edit/apply/switch/delete、双草稿/直播快照、轮廓透明度与边界、双轴滚动、独立预设 6×6 交叉、旧数据兼容，以及普通连续输入回调不触发面板重建。1.4.2 在原运行环境的完整 headless 回归为 3454 PASS / 0 FAIL；公开导出副本另行完成干净交叉编译和 player 单测，不冒称重新验证了实际 GUI 鼠标/IME/焦点。

### 代码结构

- `src/plugin-main.c`：模块入口
- `src/noticeboard.c`：来源本体（设置、草稿 / 直播快照、播放、绘制、属性窗口）
- `src/nb-text.c`：GDI 文字排版（中文逐字折行、英文按单词折行、避头标点、标题省略号）
- `src/nb-player.c`：播放时间线（独立于渲染的播放与滚动时间线）
- `data/noticeboard.effect`：圆角卡片 + 文字着色器
- `data/locale/zh-CN.ini`、`en-US.ini`：界面文字

草稿 / 直播的实现：来源设置 = 草稿；`private_settings.live` = 已应用的快照（随场景集合保存，
属性窗口「取消」不会改到它）。直播、录像、转场、滤镜都是渲染到纹理，只画快照；
只有直接画到窗口（属性窗口预览等）且草稿有改动时才画草稿并加角标。
